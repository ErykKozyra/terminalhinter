A dropdown for your terminal.

Open source autocomplete for zsh and bash. Folders, git branches, npm scripts and 600+ CLIs show up as you type, each with a short description. Enter walks into folders, and the list learns what you use.

Everything works from the keyboard.

Enter

Walk into folders

Enter on a folder opens it and keeps the list open with what is inside. The first entry, ↪, runs the command where you are, so cd and a few Enters take you deep into a project.

Shift

Put the list in your order

Move the selected entry up or down and the list keeps that order for that spot in the command. What you arrange after pnpm also applies when you type your alias p.

Tab

Nothing gets in the way

Right after a space nothing is selected, so Enter just runs the command. Up with nothing selected still walks your shell history, and git checkout - runs at once.

EscCtrlSpace

Close it, open it again

Esc hides the list until you type again. Ctrl+Space brings it back when you want to look.

macOS uses Control+Space to switch keyboard layouts when you have more than one. If it switches the layout instead of showing the list, turn that shortcut off in System Settings › Keyboard › Keyboard Shortcuts › Input Sources.

It helps when something goes wrong.

The fix for the command that just failed

A typo, a missing upstream branch, a script or branch with a near name, a folder that needs -p, a port that is taken: the empty line after the error offers the fix, and Tab puts it on the line. Nothing runs by itself.

➜ git push
fatal: The current branch login has no upstream branch.
➜ ▏
   ■ git push --set-upstream origin login

What a line does, before you run it

Ctrl+G lists every word of the line with what it means, through pipes, &&, redirects and sudo, and warns about the parts that delete or overwrite things.

➜ git reset --hard HEAD~1
  ■ git      Distributed version control system
  ■ reset    Reset current HEAD to the specified state
  ■ --hard   You will lose all uncommitted changes
  ■ HEAD~1   argument
  ⚠ --hard: throws away uncommitted changes

Entries that delete, force-push or look like production (a target tagged [prod], an ssh host called PROD) get a red mark in the list and say why when you select them.

It knows your project.

The list ranks by what you pick, recent things above old ones, and letters in order are enough: chkt finds checkout. On top of the 700 command specs it reads your project:

Your tasks

Makefile targets with the ## text next to them, grouped by section; just recipes, Taskfile tasks, docker compose services, mise and deno tasks, package.json scripts and turbo tasks.

git with context

Branches show how old their last commit is and what it says. Stashes show what they hold, git reset offers the reflog to undo, and your aliases complete like the command behind them.

The process on that port

kill starts with the processes that listen on a port: :3000 next dev · ~/Dev/shop.

Package versions

npm i react@ lists the tags and the newest releases. pnpm, yarn and bun too.

What you ran here

Typing the first word brings back whole commands you ran in this folder. Lines that look like they hold a password or a token are never stored.

Workspaces and folders

pnpm --filter and yarn workspace list your packages, and cd finds folders from anywhere through your bookmarks and zoxide.

Nothing to allow

It runs inside your terminal, so there is no Accessibility, Screen Recording or Input Monitoring to switch on, no app in the menu bar and no account. Install it and open a new tab.

Snippets with fields

Commands you type often, with fields to fill in, in ~/.config/terminalhinter/snippets.yaml. Type the name, fill the fields, and the finished command lands on the line.

- name: release
  command: 'git tag v{{version}} && git push --tags'

Your own tools

For in-house scripts, a few lines of YAML in ~/.config/terminalhinter/specs are enough:

name: deploy
subcommands:
  - name: staging
    args: { name: app, suggestions: [web, admin] }

Set it up in a minute.

  1. Install it

    One binary with its own runtime, so switching Node with nvm never breaks it. macOS and Linux; Windows and fish are experimental.

    npm i -g @erykkozyra/terminalhinter

  2. Run the setup

    Pick your shell, a theme and icons with a live preview. The setup puts its startup lines at the top of your shell config and keeps a backup.

    thint init

  3. Open a new terminal tab

    Type git or cd and the list is there. thint doctor checks the setup and tells you how to fix anything it finds, and thint update keeps it current.

Looks its best in VS Code with a little room.

A bit more space between lines, and VS Code's own color adjustment turned off, make the list look the way it was designed. No special font is needed; a modern monospace like JetBrains Mono comes closest to this page.

{
  "terminal.integrated.lineHeight": 1.3,
  "terminal.integrated.fontSize": 13,
  "terminal.integrated.minimumContrastRatio": 1,
  "terminal.integrated.gpuAcceleration": "on"
}

Questions people ask.

What is terminalhinter?

A free, open source autocomplete dropdown for the terminal. As you type in zsh or bash, it shows folders, git branches, npm scripts and the subcommands and options of more than 600 command line tools, each with a short description.

Is it an alternative to Fig or Kiro CLI?

Yes. It gives you the same kind of dropdown under the cursor, including the Enter-into-folders navigation people liked in Fig and Kiro CLI, which dropped its autocomplete in version 3.0. It runs only on your machine, needs no account and is MIT licensed. thint migrate takes the Kiro CLI, Amazon Q or Fig lines out of your shell files.

Which shells and systems does it support?

zsh and bash on macOS and Linux. It works in any terminal app, VS Code, iTerm2, Terminal.app, Ghostty, WezTerm and Kitty included. Windows, fish, PowerShell, nushell and xonsh come from the upstream project and are experimental.

Does it need Accessibility or any other permission?

No. The list is drawn inside the terminal you already have, so macOS asks for nothing: no Accessibility, no Screen Recording, no Input Monitoring, and nothing runs in the background when the terminal is closed. The same goes for Linux and Windows.

Does it send my commands anywhere?

No. What you pick and the order you set stay in a folder on your machine. Once a day it asks npm which version is the newest; thint config set updateCheck false turns that off.

How is it related to inshellisense?

It is a fork of Microsoft's inshellisense with a redesigned list, folder navigation, ranking by use, your own order, workspace and git details, themes and a guided setup. The command specs come from withfig/autocomplete.

How do I update or remove it?

thint update installs the newest version. thint uninstall takes the startup lines out of your shell config and removes its files; then npm rm -g @erykkozyra/terminalhinter.
